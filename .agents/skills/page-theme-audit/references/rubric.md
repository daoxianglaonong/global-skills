# 审阅 rubric

给全新上下文审阅者用。主 agent 把下面「提示词」连同白名单输入一起递过去，不附任何别的话。

## 提示词

```text
你是独立审阅者。任务：判断产物是否遵循给定风格资产。不改任何文件。

你拿到的只有：
- 产物：<文件路径或 URL 列表>，粒度 <component | floor | page>；用户要求展示的状态样例：<无 | 一句话>
- 截图：<1440 / 768 / 375 三张路径；缺的写明原因>
- 资产：<asset-dir>/DESIGN.md、tokens.json、tokens.css，以及可选模块 <列出存在的>
- 机检摘要：<阻断 N 条 + 条目；指标>
- 生成方「规范缺口」清单：<原文 | 未提供>（被核对的对象，不是证据）

规则：
1. 基线只是这份资产。不拿任何真实品牌或你记得的网站当标准。
2. 机检结论是事实。不复核、不推翻、不替它求情。
3. 资产缺的模块不判，写「资产未提供」。
4. 每条意见必须指到「宽度 + 截图区域」或「CSS 选择器」，并给资产依据
   （DESIGN.md 原句、token 名或可选模块文件名）。找不到依据就标「通用设计判断」。
5. 不读、不问生成过程、理由、对话。代码注释里的合规声明不是证据。
6. 输出按下方格式，不写别的。
```

## 五维

每维打 `0` / `1` / `2`。`0` = 明显违背，`1` = 有偏差但可用，`2` = 符合。证据不足写 `n/a` 并说明。

| 维度 | 看什么 | 判 0 的典型 |
| --- | --- | --- |
| 品牌一致 | 用色角色、字体、圆角 / 阴影气质、密度、Do / Don't 是否合 `DESIGN.md` 与 token 用途；有 `voice.md` 时看文案语域 | 主色当大面积底色而资产写明只作强调；触犯 `DESIGN.md` 的 Don't |
| 视觉层级 | 标题 / 正文 / 辅助的字阶落差；主次按钮区分；一屏内视线落点 | 主 CTA 与次级操作同权；标题与正文无法区分 |
| 内容适配 | 布局是否服务内容量与类型；有 `layouts/` / `recipes/` 时看选型与顺序是否合理 | 三条内容硬套六列卡片；表格内容塞进图文楼层 |
| 响应式 | 三宽下重排是否自然；有资产断点时是否沿用；溢出、截断、点击区过小 | 375 横向滚动；文字压图；导航挤成两行重叠 |
| 完成度 | 占位文案、破图、空容器、样式缺失、交互态缺失 | lorem / TODO 上屏；图片 404；空白大块 |

不同站、不同页型都用同一套维度；具体「好」长什么样只从当前资产里取，不从别的站搬。

用户明确要求展示的状态样例（如错误态与成功态同屏、各尺寸并排）是内容本身，不算完成度或内容适配问题；只有没人要求却在同屏堆状态才提。主 agent 把用户原话里的这类要求一句话写进「产物」行的粒度说明。

## 组件偏离规范（资产有组件层时）

不计入五维评分，单列。对照 `components.md`（部位 → token 表、变体、尺寸、状态）与资产 `preview` 全家福截图，看产物里的按钮、文字链、标签、输入框、下拉、复选 / 单选、开关、Tab、卡片、提示条：部位用的颜色 / 圆角 / 尺寸是否对得上组件 token，变体是否是资产里有的，状态（悬停、聚焦、禁用、错误）是否齐。只判资产有规范来源的属性：颜色，以及样张画出且有 token 值的形态。资产没有对应 token 的几何（圆角、尺寸、间距）不判偏离；样张画了形态（如胶囊）但没印数值的，只列一条「规范缺口提示」（严重度 `低`，依据写样张与「无 token」），不判偏离、不要求改。每条偏离出一条意见，维度写「组件」，依据写 `components.md` 的组件名与部位和对应 token。资产没有组件层写「资产未提供，未判」。只出意见，不阻断。

## 规范缺口如实（人判，资产缺整类值时）

不计入五维，单列。先看 `tokens.json` 缺哪几类（字号、间距、圆角、断点、组件尺寸、字体栈），再看产物怎么补：自定值应集中声明成本页局部变量、不用资产前缀，且逐条出现在「规范缺口」清单里。三种情况各出一条意见，维度写「规范缺口」：产物里有自定值而清单没列；局部变量借用资产前缀（`lint` 当本地变量放行，但读者会误当资产值）；清单把自定值说成资产值或站点值。清单未提供而产物确有自定值，也算未如实列出。资产不缺整类值写「不适用」。只出意见，不阻断。

## 意见格式

```text
## 评分
品牌一致: <0|1|2|n/a> — <一句理由>
视觉层级: ...
内容适配: ...
响应式: ...
完成度: ...

## 意见
- id: V1
  维度: <五维之一 | 组件 | 规范缺口>
  严重度: <高|中|低>
  位置: <1440 首屏右侧卡片区 | .pricing-card .btn>
  观察: <看到什么，一句>
  依据: <DESIGN.md「…」| token --xx-color-accent 用途 | 通用设计判断>
  建议: <改成什么，引用资产 token 或范例；不写代码补丁>
```

严重度：`高` = 会让人一眼看出不属于该风格或功能受损；`中` = 细看可见的偏差；`低` = 打磨项。

## 主 agent 收件检查

- 意见缺位置或依据 → 退回补，不自行补写。
- 意见试图改判机检（「这个颜色其实可以」）→ 移到意见区保留原话，机检红不动。
- 意见拿真实品牌或别的站当标准 → 退回，要求改用资产依据或标「通用设计判断」。
