# 创作模式

新页、楼层、组件。目标页可以是源站没有的页型。

## 判页型

| 请求 | 资产 | 结论 |
| --- | --- | --- |
| 楼层 / 组件 | 任意 | 直接做；有 `layouts/` 就挑最近的一条参考 |
| 整页 | `recipes/index.md` 有同类页型 | 已知页型，直接做 |
| 整页 | 无同类，或没有 `recipes/` | 新页型，先出大纲，停 |

「同类」按读者与目的判，不按名字：「GaussDB 产品页」与 recipe「产品详情」同类；
「活动报名页」与「产品详情」不同类。拿不准当新页型。

用户在本条消息里已逐层给出楼层顺序，并明说不用确认 -> 视为已确认，直接做，
摘要写「大纲由用户给定」。

## 大纲

一页一张表，不写页面代码：

```text
页型：<名称>（新页型；最近的 recipe：<id / 无>）
读者：<谁>；目的：<了解 / 决定 / 行动>

| # | 楼层 | 参考 layout | 关键内容 | 理由 |
| 1 | 首屏 | split-hero | 产品名、一句主张、主次按钮 | 读者先要知道是什么 |
| … |

缺口：<资产没有的布局或值，打算怎么处理>
```

- 参考 layout 写资产里的 id；资产没有合适的写「自定」并在理由里说为什么。
- 没有 `layouts/` 时整列写「自定」。
- 出完即回话。用户确认（或改几行）后，下一次调用按确认的大纲出页。

## 读什么

按顺序，够用即停：

1. `DESIGN.md`。
2. 匹配的 recipe（已知页型）或大纲点名的 layout。
3. 这些文件引用的证据图；没有 `evidence/` 就跳过。
4. `voice.md` 里与本页文案相关的段落。
5. `tokens.json`：查 `cssVar` 与用途；不必全读。

不读的：采集现场（`.page-theme-work/`）、其他页型的 recipe、无关 layout。

## 写

- 引入 `tokens.css`：单页用 `<link>` 指向资产。进项目时拷一份带版本号的副本（`tokens.1.4.0.css`），在入口（全局样式或根组件）引一次，组件里不再各自引；项目不要全局变量、或要与旧主题并存时，用 `css <asset> --out <副本> --scope <根选择器>` 出副本，变量只挂在该选择器下。不手改副本内容。
- 控件按 SKILL.md「组件与引用」的顺序取：
  - 项目组件库：在项目的主题覆盖层把组件样式指向资产组件 token（`--btn-bg: var(--ex-button-primary-bg)` 或直接写进组件 class），不 fork 组件。
  - `components.css`：像 `tokens.css` 一样拷副本、入口引一次；用它的 class（`.ex-button.ex-button--primary`），状态用伪类或资产约定的状态 class；不覆写它的规则，要变体就从 `components.md` 选已有变体。
  - 都不引入：照 `components.md` 的部位 → token 表写自己的 class，值只用组件 token 或语义 token。
  - 资产没有组件层：照 `DESIGN.md` 与证据图设计，摘要缺口写「组件层」。
- 规范缺口（资产整类没有字号、间距、圆角、断点、组件尺寸或字体栈）：先查 `tokens.json` 缺哪几类，
  再在页面样式开头写一个本页 `:root`（或页面根选择器）块集中声明自定值，名字用本页前缀（`--page-*`），
  不用资产前缀、不写进资产；正文只 `var()` 它们。取值凭设计判断成体系地定（如间距 4 / 8 / 16 / 24 / 40），
  不开站点、不 `capture` 源站取值。摘要「规范缺口」一行一类：类别、变量、值。
  `lint` 不查本地变量声明与 `var()` 包裹的值，所以照此写时这些类别通常不出报警；若出现
  `font-check-skipped` / `scalar-check-skipped`（按类别计数，字号与字重分开），说明还有字面值散在正文里，挪进局部变量块。
  组件只有颜色、没有尺寸时同理：`components.css` 管颜色，尺寸由本页局部变量补。
- 内容按本页目的写。recipe 给楼层顺序与节奏，layout 给结构与响应式行为；
  数量、槽位、顺序按内容取舍，不为「看着完整」补槽。
- 文案口吻照 `voice.md`；没有 `voice.md` 照 `DESIGN.md` 的语气描述，再没有就平实写。
- 不编数字：百分比、倍数、时延只用用户给的或资产里有出处的。
- 标题不写换个产品名也成立的空话。
- CTA 克制：整页一处主行动，其余降成链接或次按钮，除非 recipe 另有说法。

## 自查

`capture` 三宽后看截图，对照引用的证据图（没有证据图就对照 `DESIGN.md` 的描述）：

| 看 | 问 |
| --- | --- |
| 层级 | 缩到看不清字，首屏还分得出主次吗 |
| 留白与密度 | 与参考相比挤了还是空了 |
| 按钮与控件 | 形状、主次、尺寸像资产里的吗；有组件层时对照 `preview --components-only` 截的全家福 |
| 配图 | 风格合 `illustrations/` 或 DESIGN 描述吗；没有就少用、用纯色块 |
| 响应式 | 768、375 自然吗；375 有没有横向溢出 |

看出问题改产物，再 `lint` 一次。最多两轮；还有问题写进摘要，不硬拖。
自查是设计判断，不写成规则，不进 `lint`。
